# Technical Support

## Department
IT Support

## Document Type
Student support knowledge article

## Purpose
Provide a consistent first-line troubleshooting process for technical problems affecting university digital services.

## Overview
Technical support requests can involve pages that do not load, unexpected errors, browser problems, broken links, session failures, file-upload issues, or service behavior that differs between devices. The Copilot should identify the affected service and reproduce the problem conceptually before suggesting basic troubleshooting.

Technical guidance must remain grounded in known system behavior. The Copilot must not claim that a system is operational, degraded, or under maintenance without an authoritative status source.

## Common Questions

### A university page is not loading.
Check whether the problem is isolated to one page or affects the wider service. Retry once, use a private browser window, and try another supported browser if practical.

### I receive an error when submitting a form.
Capture the exact error text, the action being attempted, and the approximate time. Do not tell the student to repeatedly submit a transaction or academic form if doing so could create duplicates.

### A file will not upload.
Record the affected service, file type if relevant, approximate file size when known, browser/device, and exact error. Follow any documented file requirements; do not invent unsupported limits.

### Everything worked yesterday but not today.
Treat this as a possible change in service, browser state, account state, or configuration. Basic isolation steps are appropriate, followed by escalation if the failure persists.

## Step-by-Step Procedure

1. Identify the university service or feature affected.
2. Identify the exact action the student is attempting.
3. Capture the exact error message or visible symptom.
4. Record approximate time and frequency of the failure.
5. Identify browser, device, and operating environment when relevant.
6. Retry once after refreshing the page.
7. If appropriate, test in a private/incognito window.
8. If practical, test another supported browser or device.
9. Check whether the failure is limited to the student or appears broader, using only authoritative information available to the support system.
10. Escalate persistent, high-impact, security-sensitive, or system-wide issues.

## Requirements
Useful diagnostics:
- service and feature;
- action attempted;
- exact error;
- date/time;
- browser/version if available;
- device/operating system;
- steps already attempted;
- whether the same action works elsewhere.

Avoid collecting passwords, authentication codes, unnecessary personal information, or full payment information.

## Troubleshooting

**Page does not load:** refresh, private window, alternate browser, then escalate if persistent.

**Unexpected application error:** preserve exact error text and time. Avoid repeated submissions that could create duplicate records.

**Browser-specific behavior:** compare with another supported browser.

**Device-specific behavior:** determine whether the same account/action works on another device, when safe and practical.

**Service-wide symptoms:** route to IT Support rather than treating the issue as an individual configuration problem.

**Security warning:** do not instruct the student to bypass a browser security warning. Escalate the warning to IT/security support.

## Important Rules
Technical support must not become an excuse to invent system behavior. The Copilot should distinguish between documented facts, reasonable troubleshooting suggestions, and unknown system state.

It must not advise students to disable security controls, share credentials, install unapproved software, or bypass university access controls.

## When to Escalate
Escalate:
- persistent technical failure after basic troubleshooting;
- apparent service-wide outage;
- security warnings or suspected compromise;
- failures blocking exams, enrollment, payment, or another critical deadline-sensitive action;
- repeated failed submissions;
- problems requiring administrative or account changes.

## Information to Collect
Collect the smallest useful diagnostic set: service, action, symptom/error, time, environment, and attempted troubleshooting.
